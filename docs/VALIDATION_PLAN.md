## 一、組員自己的儀表板解析測試

**目的**：確認 AI 讀真實畢審儀表板的表現。訪談指出學生與承辦人看到的是同一份儀表板，所以由組員自願用本人的資料測試。

**紅線，全部要遵守：**

- 只用**本人**的儀表板，且本人同意；不收集、不轉傳別人的資料。
- **不能用免費方案的金鑰**。免費方案的內容會用於改進產品，也可能經人工審閱。沒有付費或機構金鑰，這項就不做。
- 啟動時**不可設定 `ACADEMIC_TWIN_RECORD=1`**，否則模型回應會寫進會進版控的 `data/replay/`。
- PDF、截圖、對照結果都留在自己電腦，不進 repo、不傳群組，也不貼給任何 AI 助理。只交下方紀錄表。

**步驟：**

1. 取得最新 `main`，在 repo 根目錄的 `.env` 設好付費金鑰。
2. 登入校務系統打開自己的畢審儀表板。先按 F12，用開發者工具把頁面上的**姓名、學號**改成「測試」，再按 Ctrl+P 另存為 PDF，檔名用 `P1.pdf`（P1 依序編號）。
3. 檢查 PDF：用 Ctrl+F 搜尋自己的姓名與學號，要搜不到，檔案屬性裡也不能有；能選取文字才算文字型 PDF，掃描影像不適用。
4. 在 PowerShell 確認環境變數：`Test-Path env:ACADEMIC_TWIN_RECORD` 要回 `False`。
5. 執行 `python web.py`，開 `http://localhost:8000/office.html`，在 AI 解析區上傳 `P1.pdf`，學號填 `P1`，記下等待秒數。
6. 在畫面上逐列對照原始 PDF，把錯誤數填進紀錄表。**不要按確認送入審查**。
7. 關掉伺服器，刪除 `data/office_state/` 與 `P1.pdf`，再跑 `git status`，確認 `data/replay/` 沒有新增檔案。

**預期狀況**：系統目前只支援虛構版型，真實規則代碼不在對照表內，很可能跳出規則代碼錯誤，也可能整份解析失敗。這些都照實記錄，不要為了讓結果好看而改提示後重測；真的要改，改完的結果要分開報告。

**紀錄表（每人一列，不寫課名或成績）：**

| 代號 | 文字型 PDF | 儀表板總列數 | AI 擷取列數 | 漏列 | 多列 | 課號錯 | 課名錯 | 學分錯 | 成績錯 | 學期錯 | 規則代碼錯誤提示 | 等待秒數 | 解析失敗 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| P1 | | | | | | | | | | | | | |

**進報告的寫法**（放 3.1 與 3.6）：「N 位組員自願以本人儀表板、去除姓名學號後測試，共 X 列，欄位正確 Y／Z，規則代碼對照尚未支援真實代碼。」只有彙總數字，不寫個別結果。樣本是組員本人，不能當成全校準確率。

## 二、學生端小型使用測試

**目的**：比較學生只看原始儀表板和使用學生端時，找出重點的正確率與時間。全程使用虛構學生，不收集受測者的個人資料。

**準備（主持人）：**

1. 以評審模式啟動：PowerShell 執行 `$env:ACADEMIC_TWIN_REPLAY="only"; python web.py`。
2. 開 `http://localhost:8000/office.html#monitor`，按「載入示範批次」，選 `data/samples/demo_batch/` 的 DEMO-D03 到 D08 六份 PDF，依 [DEMO_OFFICE](DEMO_OFFICE.md) 全部不修改確認。
3. 到「學生」分頁開 DEMO-D03，把 114-1 的 `XFER-01` 覆核為本系選修。
4. 確認 `student.html?id=DEMO-D03` 顯示 100 學分，`student.html?id=DEMO-D05` 顯示 133 學分。

**分組（抵銷學生差異與練習效果）**：依報到順序輪流分配，每人都做兩種方式。

| 組 | 第一輪 | 第二輪 |
|---|---|---|
| A | 看 DEMO-D03 的 PDF | 用學生端看 DEMO-D05 |
| B | 看 DEMO-D05 的 PDF | 用學生端看 DEMO-D03 |

**流程**：先說明「測的是系統，不是你」，資料全為虛構，隨時可停止。每輪開始計時，答完 5 題按停；不提示、不解釋；每輪最多 5 分鐘，超時未答的題目算錯。

**題目（兩輪相同）：**

1. 距離最低畢業學分 128，還差幾學分？
2. 系訂必修還缺哪幾門課？
3. 通識（14 學分）還差幾學分？
4. 有沒有多修、可能沒被校務系統算進去的學分？是哪一類、幾學分？
5. 接下來需要找承辦單位辦什麼事？

**標準答案（主持人保留，不給受測者）：**

| 題 | DEMO-D03 | DEMO-D05 |
|---|---|---|
| 1 | 28 學分 | 0 學分（已達 133） |
| 2 | IM3031、IM4001、IM4048 | 沒有缺 |
| 3 | 5 學分 | 0 學分 |
| 4 | 國文，2 學分 | 通識，3 學分 |
| 5 | 確認國文超修學分的人工認列 | 確認通識超修學分的人工認列 |

**紀錄表（只用代號，不記姓名學號）：**

| 代號 | 組 | PDF：答對題數／5 | PDF：秒數 | 學生端：答對題數／5 | 學生端：秒數 | 學生端清楚程度 1–5 | 意見 |
|---|---|---|---|---|---|---|---|
| U1 | A | | | | | | |

**進報告的寫法**（放 3.1 與 3.4）：列出人數、兩種方式的答對題數與秒數中位數，第 1–3 題和第 4–5 題分開列。必須註明：受測者是同學、樣本小、使用虛構案例、題目由團隊設計，第 4–5 題本來就是學生端專門呈現的內容，只能說明初步可用性，不代表教務處實際節省的工時。

## 三、請承辦人看 demo

由負責人自行寄出，以下是草稿；對方沒回就照實寫「尚未取得回饋」，不要催促到讓對方為難。

> 主旨：想請您花 5 分鐘看一下畢審輔助系統的示範
>
> 承辦人您好：
>
> 我們是 10 月 14 日向您請教畢業審查作業的團隊，謝謝您當時的協助。依您的建議，我們已先完成資管系的版本，全程只使用虛構資料。
>
> 比賽將於 11 月 11 日晚上截止，想請問您是否方便撥 5 分鐘看一段示範（線上或到辦公室都可以）？看完只想請教一句話：這樣的流程對您的工作有沒有幫助，或哪裡還不足。
>
> 如果您同意，我們會在報告中以「教務處承辦人」的稱呼引用您的回覆，不會寫出姓名；若不方便引用或沒有時間，完全沒有關係。
>
> 謝謝您！

**示範順序（5 分鐘）**：監控台分流與抽查 → DEMO-D07 無法交叉驗證的警示 → 收件匣擬稿與依據 → 學生端的「可能是校務系統誤判」。

**紀錄**：逐字記下對方同意引用的那一句，放進報告第一章或 3.6。批評也一樣照實寫，評審會更相信。
