# 成果報告書設計

更新日期：2026-11-09。本文件規劃 2026 AI 校務治理實務競賽成果報告書的章節、論證與證據，報告本文另外撰寫。報告須於 115-11-11 23:59 前寄出；初審只看報告書與影片。

## 設計原則

- **一條主線**：畢審最後仍靠人工逐份查看；本系統讓 AI 提案、規則引擎判定、承辦人確認，人只處理例外。
- **寫給評審看**：評分四項各占 25%，每章開頭第一句寫結論，並對應到一項評分。
- **數字帶範圍**：每個數字都寫樣本數、資料性質與限制。目前的量測全部來自虛構案例，不寫成真實準確率或節省工時。
- **照實寫限制**：實證性看的是方法是否扎實，主動寫出沒驗證到的部分，比含糊帶過更有說服力。
- **用詞**：一律寫「教務處」「教務處承辦人」。受訪者是教務處負責資管系畢審的承辦人。
- **引用**：公開數據與第三方素材要標註來源與授權（簡章規定）。

## 單位因應策略

這章寫的是團隊的建議，不寫成學校已同意的事項。

| 面向 | 建議內容 |
|---|---|
| 教務處 | 承辦人從逐份查看改為處理例外；維持最終確認權；提供人工答案與計時，作為真實驗證基準 |
| 系所 | 確認該系規則草稿與例外認定；新年度規則的核定者待確認 |
| 資訊與校務研究單位 | 評估資料傳輸與保存、金鑰管理、帳號權限；協助彙整導入成效 |

| 階段 | 做法 | 進入下一階段的條件 |
|---|---|---|
| 1. 並行試用 | 資管系一個畢審週期，與人工流程並行，只用經確認可用的去識別化資料 | 判定一致率、誤報與漏報、實際工時達到雙方約定的標準 |
| 2. 資管系導入 | 補齊登入、權限、覆核人身分、資料保存 | 通過校內資料與資安審查 |
| 3. 規則明確的系所 | 用 AI 草擬規則擴充規則庫，由各系確認（承辦人建議的擴散路徑） | 各系規則通過預覽比對 |
| 4. 複雜情境 | 輔系、雙主修、學分學程，依申請當年度規則審查 | — |

穩定性與維運可寫的現況：不需介接校務系統；AI 失敗或停用時改走人工；有每月 token 預算上限；規則依入學年度管理。費用若放數字要標明是估算，建議的模型組合尚未以基準集量測。

## 安全合規要照實寫

- **已有的做法**：AI 不能改變判定；收件匣與 What-if 限制送給模型的內容；執行軌跡不記學號、成績與原文；回信只擬稿，不串接真實寄信。
- **還沒有的**：覆核人身分驗證、學生登入、正式權限控管、資料保存機制。不得宣稱已完成全面安全合規。
- **儀表板內容會送至 Gemini**：目前只處理虛構或去識別化文件；去識別化不代表自動取得外傳授權，正式導入前要先確認。
