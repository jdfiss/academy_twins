# 學生端需求

更新日期：2026-11-09（本學期修課試算）；2026-11-08（現況與限制）；需求內容 2026-10-14。架構以 [專案設計與主要流程](PROJECT_DESIGN.md) 為準；學生常見問題來自 [2026-10-14 承辦人訪談](MEETING_NOTES_2026-10-14.md)。

## 業務背景

學生與承辦人看到的是同一份校務系統畢審儀表板。儀表板依全校共用的規則代碼分欄，學生常看不懂代碼意義，也不知道系統顯示「不合格」是真的缺課，還是校務系統的限制。這類疑問透過電話與 Gmail 湧入承辦人，需一封一封查完回覆。

學生端是專案最初的「學業分身」：依學生的修課紀錄與規則，呈現目前進度，並往後推演修課路徑、預估畢業學期與各種情境的延畢影響。它也讓學生先自行理解進度與需辦理的事項，減少重複詢問承辦人。

## 學生常見問題與對應功能

| 學生常問的事 | 學生端的處理 |
|---|---|
| 超修的學分為什麼沒算進去 | 標出各類別超修學分，說明可能可由承辦人人工移入其他類別 |
| 同課號修了好幾次卻顯示不合格 | 辨識可重複修習的課程，說明這是校務系統限制及需找誰處理 |
| 看不懂規則代碼名稱 | 將系統代碼對照章則用語並以白話說明 |
| 必修停開了怎麼辦 | 提示可辦理抵修（課程替代），抵修前系統仍會顯示缺課 |
| 轉學、轉系後的學分 | 列出需辦理的抵免或抵修事項 |

## 個人修業進度

使用者為在學學生，查詢自己的畢業進度。

輸入：學生自己的畢審儀表板或修課紀錄；入學年度與系所由資料或身分帶入。

輸出：各要求的已達成數量與缺額、缺少的必修、選修條件、超修學分、可能被校務系統誤判的項目、需找承辦人辦理的事項，以及各項的規章依據與白話說明。

驗收條件：

- 同一份資料在學生端與學校端得到相同判定。
- 依學生入學年度的規則審查，延畢生亦同。
- 結果明確標示為「試算」，不是正式審查結果。
- 校務系統可能誤判的項目與真正缺修分開呈現；結果標示「試算」，正式結果以系辦審查為準。
- 需人工辦理的項目指出要找的單位或承辦人。
- 學生只能查看自己的資料。

## 修課規劃與 What-if

使用者為在學學生，用於選課前安排後續修課。

輸入：個人修業進度、課程先修關係、開課學期、本學期正在修的課（還沒有成績，由學生自行輸入），以及情境（某門課不修、某學期出國交換）。

輸出：到畢業的各學期修課建議、預估畢業學期，以及情境造成的延畢影響與受影響課程。

驗收條件：

- 遵守正式先修、開課學期與每學期學分上限。
- 情境模擬列出受影響課程及延後學期數。
- 開課學期若為推估而非實際開課資料，需明確標示。
- 停開課程需能反映，並提示替代課程或抵修。

## 待決事項

- 承辦人的覆核、人工認列與抵修結果是否同步到學生端；不同步時兩端結果可能不一致。
- 學生身分驗證方式與資料取得方式（學生自行上傳或由校務系統帶入）。
- 實際開課資料來源（課務組）。
- 輔系、雙主修、學分學程依申請年度規則的試算，列為後續階段。

## 現況與往後方向

已有雛形（網頁「學生 Academic Twin」、命令列 `--plan`、`--skip`、`--away`、`--course`、`--bottlenecks`）：畢業進度逐條結果、到畢業的修課路徑、某課某學期不修與出國交換的 What-if（延畢學期數與受影響課程）、課程影響範圍、瓶頸課排行。

已完成：

- 介面比照系辦端（2026-11-09）：字級一致、不用說明用小字；畢業條件只列缺修與規章依據，原本每條要求的白話說明與系統代碼對照已移除。
- 誤判提示與真正缺修分開呈現、需辦理事項與承辦單位。
- What-if 結果對比（原本／模擬後畢業學期、延畢學期數、被往後推的課）與開課學期推估標示；出國交換可設定連續 1–4 學期。
- AI 自然語言 What-if：學生用一句話提問，AI 只轉成模擬條件，程式檢核後由學生確認，再由規劃器計算；轉不出條件或服務無法使用時改用手動選項。目前以替身模型測試。
- 本學期修課試算：學期中成績還沒出來，修課紀錄只到上學期。學生可在「修課規劃與 What-if」輸入本學期修的課；勾選的課假設會及格，交給審查引擎重新審查後再規劃，規劃從下一學期開始；取消勾選的課（打算停修、可能沒過）視同沒修，規劃器會重新排入。規則庫有的課，課名與學分以規則庫為準。挑課選單列出本學期資管系與管理學院的開課（取自學校課程查詢系統；示範用的未來學期依實際學期模擬並標示），通識、外系課手動輸入。輸入只存在學生的瀏覽器，伺服器不保存；正式審查結果不受影響。What-if 與 AI 自然語言 What-if 都會一併套用。

尚待建置：

- 用語對照的實際系統代碼（待承辦人提供）。
- AI 自然語言 What-if 以真實模型量測轉換正確率。
- 推演改用學生入學年度規則：審查結果已依入學年度判定，但修課路徑與 What-if 仍用預設的 114 規則庫。目前只有 114 正式規則，兩者結果相同；加入其他年度規則前須先改。

比賽期間的範圍與優先序見 [兩組分工計畫](TEAM_PLAN.md#b-組學生端推演)。

驗收條件尚未做到的部分：

- **學生只能查看自己的資料**：尚無登入，學生頁可選任一學生代號試算。
- **停開課程需能反映**：只在已修過替代課時提示辦理抵修；規劃器不會自動改排替代課。

往後方向：

- 自然語言提問擴充到 What-if 以外的問題（例如問缺什麼、該找誰辦），仍依審查與計算結果以白話回答。
- 延畢預警：每學期成績進來自動重算，路徑來不及時主動提醒，並可提供導師與系辦。
- 更多情境：重修、休學、提早畢業、調整每學期修課量。
- 加修輔系、雙主修、學分學程的試算（依申請年度規則）。
- 多個方案並排比較。
- 選課前建議：開課資料擴及通識與外系、規劃器依實際開課排課，停開課自動改排替代課。
